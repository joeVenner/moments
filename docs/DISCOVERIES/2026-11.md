### Moment upload paths (detail)
- **Images, and videos when Stream is disabled, up to 512 MB** → resumable S3
  multipart direct-to-R2 (`client/lib/multipartUpload.ts` + `worker/multipartPresign.ts`
  + `/api/events/:slug/moments/multipart/*`). Files split into 8 MiB parts that the
  browser PUTs straight to R2 (Worker never sees bytes); 3 parts in flight per file,
  large files globally serialized to avoid mobile network overload. Metadata persisted
  in IndexedDB, bytes in OPFS. Queue resumes from R2 `ListParts` on startup, reconnect,
  visibility return, or Background Sync. A root-scoped service worker
  (`client/uploadServiceWorker.ts`) uploads staged files while the browser grants
  background execution; iOS resumes when the page is runnable again. An interruption
  costs at most one ~8 MiB part. Screen wake lock is a foreground optimization only.
- **Videos when Stream is configured** → Cloudflare Stream direct-creator `tus`
  upload (`client/lib/streamUpload.ts` + `/moments/stream/{session,tus,complete,abort}`).
  Worker proxies only the authenticated creation request; bytes go browser→Stream.
  Client persists tus URL + file in the same queue, then renders the adaptive Stream
  iframe. Needs `STREAM_ACCOUNT_ID`, secret `STREAM_API_TOKEN` (Stream Edit),
  `STREAM_CUSTOMER_CODE`; missing config is detected and falls back to R2.
- Legacy native `POST /moments` 25 MB route kept for compatibility; the guest UI sends
  every new moment through a durable path so the upload manager covers all items.
- **Retired:** on-device WebCodecs video optimizer (`optimizeVideo.ts`) is not exposed
  in the UI — even high-end iPhones throttle/suspend long transcodes. Any future video
  processing should be server-side.

### Banner system (detail)
- **No-cover fallback** = live, type-aware CSS scene (`client/lib/eventBanners.tsx`):
  one dark-native preset per event type (Wedding/Gala/Birthday/Corporate/Other) with a
  slow motif animation (drift/sparkle/confetti/scan/rings). Used by the event hero and
  admin `EventPreview`. Motion gated by `prefers-reduced-motion`.
- **Prebuilt pickable banners** (`client/lib/sampleBanners.ts`) are the static cover
  override when AI generation fails. Rasterized to PNG and sent through the real
  `cover` upload path (backend trusts only real uploads / `/media/` URLs). Repainted
  dark-native 2026-06; `sampleBannerIdForType(type)` pre-selects the matching swatch.

### Admin/event feature set (migrations 0005–0008)
Moderation, event expiry/archive, PBKDF2-protected private events, reactions,
highlights. Daily 03:00 UTC cron deletes expired event media + owned D1 rows. Private
media checks an HttpOnly event-access cookie. Admin galleries: selected/full streaming
ZIP export (`fflate`, dynamically imported), bulk moderation, storage/activity
analytics, five event templates with retention defaults.

## [2026-11-16] Context Update — private-event access hardening (iOS plan, Phase 0a)
- **What changed:** Signed HMAC access grants bound to `events.access_version`
  (migration `0009`), PIN throttling via `access_failures`, 6-char minimum for new
  PINs, fail-closed 503 without `EVENT_ACCESS_SECRET`.
- **Why:** The raw `invite_token` cookie never rotated and the 4-digit PIN was
  brute-forceable; native clients also need the grant in the response body.
- **Impact:** `worker/eventAccess.ts`, `/access` + admin PATCH + gate + `/media` in
  `worker/index.ts`, `lifecycle.ts` (cleanup + daily prune), admin UI.
- **Reference:** `c7a9441`, `11f7f36` on `feat/event-access-hardening`.
- **Lessons:**
  - Making an access check async is dangerous: `!promise` is always false, so a
    missed call site fails open. Rename the function so old call sites stop compiling.
  - D1 check-then-insert throttling races. Insert the attempt row first, count
    including it, and delete it on success.
  - A hard per-event lockout lets one attacker lock out a live wedding. Use a
    per-client cap, an event-wide slowdown before blocking, and never throttle the
    invite link.
- **Follow-ups:** remove the legacy raw-token path after 2027-01-15
  (`LEGACY_RAW_TOKEN_ACCEPTED_UNTIL`); add a host "revoke access / new link" action
  that doesn't require a new PIN.

## [2026-11-17] Context Update — per-device guest tokens (iOS plan, Phase 0)

  only) and `participants.claimed_at`. `POST /participants` returns a
  `guest_token` to the request that wins the nickname (new or legacy-unclaimed).

  New `src/worker/testing/sqliteD1.ts` runs tests on the real migrations;

- **Why:** Native clients need a stable anonymous identity; nicknames alone can

  `worker/index.ts`, `lifecycle.ts`, `client/lib/{api,nickname}.ts`.
- **Deploy order:** apply migration `0010` remotely **before** deploying the

    farmed then stay valid after the switch and can evict the owner.
  - Claim + session insert must be one `db.batch`. SQLite `changes()` inside
    `INSERT ... SELECT ... WHERE changes() = 1` refers to the previous statement
    in the batch, so the upsert `ON CONFLICT DO UPDATE ... WHERE claimed_at IS NULL`
    gates the session insert atomically (verified on local D1).
- **Before enabling enforcement (follow-ups):**
  - Web: call join on load when a nickname is stored but no token is, and show
    `nickname_taken` in the nickname gate (today `joinEvent` swallows non-OK).
  - Recovery for a guest who lost their token (host can reset a claim).
  - Uploads/reactions still identify by nickname (`upsertParticipant` creates
    unclaimed rows); bind them to the token in the upload slice.
  - Per-IP join rate limiter + per-event participant cap (ties into guest caps).

## [2026-11-17] Context Update — cursor feed (iOS plan, Phase 0)
- **What changed:** Migrations `0011`–`0012` add per-event `event_feed_counters`,
  `moments.seq`/`change_seq`, `moment_tombstones`, a backfill, and three triggers
  (insert stamps seq+change_seq; hide/unhide/caption bumps change_seq; delete
  writes a tombstone). New `worker/feed.ts` + routes `/feed` and `/feed/changes`.
- **Why:** The iOS app needs stable paging and cheap "what changed" polling;
  offset paging shifts under new uploads.
- **Impact:** `worker/feed.ts`, `worker/index.ts` (2 routes), `lifecycle.ts`
  (drops tombstones on cleanup), `testing/sqliteD1.ts` (batch returns rows,
  `stopBefore` for backfill tests).
- **Deploy order:** apply `0011`–`0012` remotely **before** deploying the worker.
- **Lessons:**
  - Triggers beat touching every write path: three upload inserts, moderation,
    deletes and cleanup are all covered, and new paths can't forget.
  - A global counter leaks other events' activity to any guest. Counters are
    per event; the unique index is `(event_id, seq)`.
  - `(? IS NULL OR seq < ?)` defeats the index; bind a max-int sentinel instead.
    A partial index `WHERE moderation_status = 'approved'` makes pages a seek.
  - Backfill ties: `created_at` has 1 s resolution, so order by `rowid` after it.
  - Keep the non-retryable `ADD COLUMN` in its own migration, but put backfill
    and triggers in ONE file: with triggers in a later file, an upload landing
    between them keeps `seq = NULL` forever and never reaches the feed.
  - Triggers create their counter row first (`INSERT OR IGNORE`) so a missing
    row can't null a NOT NULL column and abort a delete or hide.
- **Follow-ups:** rate-limit guest polling (`/feed/changes`) with the join
  limiter; reaction counts in `upserts` can be stale (not tracked by
  `change_seq`); cleanup writes ~3x rows per moment because of the tombstone
  trigger (acceptable while archives are rare); a first `since=0` poll returns
  ids of hidden moments (ids only, no content).

## [2026-11-17] Context Update — Stream signed URLs (iOS plan, Phase 0)
- **What changed:** `worker/streamSigning.ts` mints RS256 Stream tokens with
  the signing key in `STREAM_SIGNING_KEY_ID` + `STREAM_SIGNING_JWK` (base64
  `jwk` from `POST /stream/keys`). When both are set, the following apply to
  private events:
  - tus uploads get `requiresignedurls`;
  - every Stream URL returned (web moments/highlights/feed/changes, admin
    list + moderation PATCH, stream/complete, v1 feed/changes) has the uid
    replaced by a token;
  - `stream/complete` locks the video before committing;
  - access-settings saves sync `requireSignedURLs` for the event's videos.
- **Why:** Private videos were playable by anyone holding the 32-hex uid.
- **Rollout (Yassir):**
  1. Deploy (no migration).
  2. `POST /accounts/<id>/stream/keys`.
  3. `wrangler secret put STREAM_SIGNING_KEY_ID` and `STREAM_SIGNING_JWK`.
  4. Re-save each private event's access settings to lock existing videos.
  5. Check logs for `stream_signing_synced` with `failed > 0` and re-save
     those events.
- **Behaviour:**
  - Tokens: `exp` = next hour boundary + 1 h (1–2 h validity, stable within
    the hour so URLs cache). They are bearer tokens shared by all guests in
    that hour; the only revocation is deleting the signing key.
  - A bad key gives 503 `stream_signing_unavailable` (fail closed); the
    secret is never logged.
  - Upload-Metadata is an allowlist: `name`, `filetype`, `maxdurationseconds`.
- **Lessons:** Stream's edit-video API is `POST /stream/<uid>` with a partial
  body; `JSON.parse` errors can quote their input, so secret parsing must
  rethrow fixed messages.
- **Follow-ups:**
  - The sync is one subrequest per video in `waitUntil`; very large events on
    the free plan can hit the subrequest limit (re-save retries). Move it to a
    queue with lifecycle.
  - The admin list signs up to 500 tokens on a cold isolate (CPU).
  - Pre-existing: routes still using `getEventBySlug` (stream session/abort,
    multipart, participants, leaderboard, reactions) skip the private gate
    for archived events.

    omitted otherwise keeps its stored value; close after purge is a 400.
    `normalizeDate` rejects years outside 2000–2100.
- **Why:** plan states need read-only windows (uploads closed, data kept
  for download) before deletion. Legacy events (split columns null) are
  unchanged: uploads stop, event 404s, cron purges, all at expires_at.
- **Deploy order:** `npm run db:migrate:remote` (0015), then `npm run deploy`.

    admin just shortened (auditor MEDIUM).

## [2026-11-17] Context Update — orphan multipart abort (iOS plan, Phase 0)
- **What changed:** `src/worker/orphanUploads.ts`. The daily cron (after
  `cleanupExpiredEvents`, sequentially) aborts up to 40 open R2 sessions,
  6 in parallel, picked at random: older than 7 days, or past the event's
  upload close plus the 30 min grace. `cleanupEvent` aborts the event's open
  sessions (cap 25) before deleting its rows; failures there are logged and
  never block the purge, and one failing event no longer stops the others.
  Only `uploads` rows with a non-empty upload id and a key inside
  `events/<event_id>/moments/` are touched (Stream rows share the table).
- **Why:** unfinished multipart parts are billed and invisible to
  `BUCKET.list`; purges deleted the rows that pointed at them.
- **Deploy:** no migration; `npm run deploy`. Check the bucket has an
  AbortIncompleteMultipartUpload lifecycle rule (R2 default: 7 days) as the
  backstop.
- **Lessons:**
  - `uploads` holds Stream rows too (`stream-session/…`, `stream/…`); an S3
    abort on them 404s, which counts as success and would mark them aborted
    without deleting the Stream asset.
  - The web queue resumes paused uploads days later and does not recover
    from an aborted session (part-url 404 → paused forever), so the age
    threshold must not undercut R2's own 7-day expiry.
  - Oldest-first batches let permanently failing rows starve the reaper.
- **Follow-ups:** web client: on part-url 404 / aborted status, discard the
  session and re-init from OPFS. Stream orphan reaper (Stream DELETE).
  Per-event cap on open sessions at init (no limiter today).

  plugin (types + client, `internal`), public `MomentsClient` conforming to

    a decode error and lose the status; `NonJSONErrorMiddleware` fixes it.
  - Build plugin needs trust: Xcode prompts once; `xcodebuild` (CI, Xcode
    Cloud) needs `-skipPackagePluginValidation`.
  - `CFBundleVersion` must be 1-9 digits or the server ignores `X-Client`
