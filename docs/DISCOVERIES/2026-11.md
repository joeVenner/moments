### Moment upload paths (detail)
- **Images, and videos when Stream is disabled, up to 512 MB** → resumable S3
  multipart direct-to-R2 (`client/lib/multipartUpload.ts` + `worker/multipartPresign.ts`
  + `/api/events/:slug/moments/multipart/*`). Files split into 8 MiB parts that the
  browser PUTs straight to R2 (Worker never sees bytes); 3 parts in flight per file,
  large files globally serialized to avoid mobile network overload. Metadata persisted
  in IndexedDB, bytes in OPFS. Queue resumes from R2 `ListParts` on startup, reconnect,
  visibility return, or Background Sync. A root-scoped service worker
  (`client/uploadServiceWorker.ts`) uploads staged files while the browser grants
  background execution; iOS resumes when the page is runnable again. An interruption
  costs at most one ~8 MiB part. Screen wake lock is a foreground optimization only.
- **Videos when Stream is configured** → Cloudflare Stream direct-creator `tus`
  upload (`client/lib/streamUpload.ts` + `/moments/stream/{session,tus,complete,abort}`).
  Worker proxies only the authenticated creation request; bytes go browser→Stream.
  Client persists tus URL + file in the same queue, then renders the adaptive Stream
  iframe. Needs `STREAM_ACCOUNT_ID`, secret `STREAM_API_TOKEN` (Stream Edit),
  `STREAM_CUSTOMER_CODE`; missing config is detected and falls back to R2.
- Legacy native `POST /moments` 25 MB route kept for compatibility; the guest UI sends
  every new moment through a durable path so the upload manager covers all items.
- **Retired:** on-device WebCodecs video optimizer (`optimizeVideo.ts`) is not exposed
  in the UI — even high-end iPhones throttle/suspend long transcodes. Any future video
  processing should be server-side.

### Banner system (detail)
- **No-cover fallback** = live, type-aware CSS scene (`client/lib/eventBanners.tsx`):
  one dark-native preset per event type (Wedding/Gala/Birthday/Corporate/Other) with a
  slow motif animation (drift/sparkle/confetti/scan/rings). Used by the event hero and
  admin `EventPreview`. Motion gated by `prefers-reduced-motion`.
- **Prebuilt pickable banners** (`client/lib/sampleBanners.ts`) are the static cover
  override when AI generation fails. Rasterized to PNG and sent through the real
  `cover` upload path (backend trusts only real uploads / `/media/` URLs). Repainted
  dark-native 2026-06; `sampleBannerIdForType(type)` pre-selects the matching swatch.

## [2026-11-16] Context Update — private-event access hardening (iOS plan, Phase 0a)
- **What changed:** Signed HMAC access grants bound to `events.access_version`
  (migration `0009`), PIN throttling via `access_failures`, 6-char minimum for new
  PINs, fail-closed 503 without `EVENT_ACCESS_SECRET`.
- **Why:** The raw `invite_token` cookie never rotated and the 4-digit PIN was
  brute-forceable; native clients also need the grant in the response body.
- **Impact:** `worker/eventAccess.ts`, `/access` + admin PATCH + gate + `/media` in
  `worker/index.ts`, `lifecycle.ts` (cleanup + daily prune), admin UI.
- **Reference:** `c7a9441`, `11f7f36` on `feat/event-access-hardening`.
- **Lessons:**
  - Making an access check async is dangerous: `!promise` is always false, so a
    missed call site fails open. Rename the function so old call sites stop compiling.
  - D1 check-then-insert throttling races. Insert the attempt row first, count
    including it, and delete it on success.
  - A hard per-event lockout lets one attacker lock out a live wedding. Use a
    per-client cap, an event-wide slowdown before blocking, and never throttle the
    invite link.
- **Follow-ups:** remove the legacy raw-token path after 2027-01-15
  (`LEGACY_RAW_TOKEN_ACCEPTED_UNTIL`); add a host "revoke access / new link" action
  that doesn't require a new PIN.

## [2026-11-17] Context Update — per-device guest tokens (iOS plan, Phase 0)
- **What changed:** Migration `0010` adds `guest_sessions` (SHA-256 token hash
  only) and `participants.claimed_at`. `POST /participants` returns a
  `guest_token` to the request that wins the nickname (new or legacy-unclaimed).
  `GUEST_TOKENS_ENFORCED=true` turns contested joins into `409 nickname_taken`.
  New `src/worker/testing/sqliteD1.ts` runs tests on the real migrations;
  `tsconfig.worker-test.json` keeps Node types out of production worker code.
- **Why:** Native clients need a stable anonymous identity; nicknames alone can
  be claimed by anyone.
- **Impact:** `worker/guestIdentity.ts`, join + `GET /participants` in
  `worker/index.ts`, `lifecycle.ts`, `client/lib/{api,nickname}.ts`.
- **Deploy order:** apply migration `0010` remotely **before** deploying the
  worker; the new join route queries `claimed_at` and `guest_sessions`.
- **Lessons:**
  - Never mint a token on a contested join, even before enforcement: tokens
    farmed then stay valid after the switch and can evict the owner.
  - Claim + session insert must be one `db.batch`. SQLite `changes()` inside
    `INSERT ... SELECT ... WHERE changes() = 1` refers to the previous statement
    in the batch, so the upsert `ON CONFLICT DO UPDATE ... WHERE claimed_at IS NULL`
    gates the session insert atomically (verified on local D1).
- **Before enabling enforcement (follow-ups):**
  - Web: call join on load when a nickname is stored but no token is, and show
    `nickname_taken` in the nickname gate (today `joinEvent` swallows non-OK).
  - Recovery for a guest who lost their token (host can reset a claim).
  - Uploads/reactions still identify by nickname (`upsertParticipant` creates
    unclaimed rows); bind them to the token in the upload slice.
  - Per-IP join rate limiter + per-event participant cap (ties into guest caps).
