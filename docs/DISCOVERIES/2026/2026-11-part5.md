## [2026-11-19] Context Update — iOS "Your events" home
- **What changed:**
  - `EventCredentialStore.storedSlugs()`: the keychain store lists its own service's items with `kSecReturnAttributes` + `kSecMatchLimitAll`, so listing never reads a token. Accounts that aren't valid slugs are skipped.
  - `FeatureGuest/MyEventsModel`: an event counts as joined when it has a stored guest token. Each one is fetched with that token plus any unexpired grant. `eventNotFound` drops the event, `accessRequired` shows it as locked (opening asks for the PIN), and other errors keep it openable with the slug as its title. The list is sorted newest start first. Fetches run one after another, which is fine for a handful of events.
  - `HomeView` lists the events above the link field and reloads whenever home appears and on pull to refresh.
  - `AppNavigation.open(_:)` and `goHome()` drop any pending invite and reset the duplicate-link window. `GuestEventView` gains an optional `onHome` (a chevron in its top bar and above the join screen); the App Clip will pass nil. Leaving an event also returns home through `goHome()`.
- **Why:** Yassir asked for a proper app home (2026-11-19); a guest needs a way back to events they have joined.
- **Lessons:** `ImageRenderer` renders a `ScrollView` blank, so render the content without it when screenshotting from tests. `String(localized:)` follows the process locale, not `\.locale`.

## [2026-11-19] Context Update — iOS QR scanner
- **What changed:**
  - `ios/Moments/QRScanner.swift` wraps VisionKit's `DataScannerViewController`, set to QR codes only with one item at a time.
  - Each code's text goes through `AppNavigation.handle(text:)`, the same checks as a pasted link: https, the moments-hq.com host, an event path, at most 2048 characters. The `ScanFilter` stops a refused code from being announced on every frame.
  - The Home "Scan QR code" button shows only when `DataScannerViewController.isSupported`, so the simulator never shows it. When the scan button is present, "Open event" uses the new `.momentsSecondary` style, so the screen has a single orange button.

  - `NSCameraUsageDescription` is set through `INFOPLIST_KEY_*` (Debug and Release). French comes from the new `ios/Moments/InfoPlist.xcstrings`, compiled to `fr.lproj/InfoPlist.strings` (checked in the built app).

- **Decisions:** there is no AVFoundation fallback. DataScanner needs an A12 or later, which every iOS 17 device has.
- **Lessons:** `ImageRenderer` draws a `UIViewControllerRepresentable` as a yellow "unsupported" placeholder.

## [2026-11-19] Context Update — host sessions (server)
- **What changed:**
  - Migration `0021_host_sessions` and `src/worker/hostSessions.ts`. A token is `hs_` + 32 random bytes; the database stores only its SHA-256, a 30-day expiry, and a `credential_tag`.
  - The tag is an HMAC of the admin credentials under `EVENT_ACCESS_SECRET` (length-prefixed, domain `host-credentials:`). It is checked on every request, so changing `ADMIN_USER`, `ADMIN_PASSWORD` or the secret ends every session.
  - Sign-in compares HMACs with `timingSafeEqual`, so neither the username nor the password length leaks.
  - v1 routes:
    - `POST /admin/session` returns 201 with the token once.
    - `GET /admin/session` returns the subject and expiry.
    - `DELETE /admin/session` deletes the row (204).
  - `hostGate` on `/api/v1/admin/*` requires `Authorization: Bearer`; otherwise it answers 401 `host_auth_required` with `WWW-Authenticate: Bearer`.
  - A `hostSession` http-bearer security scheme is added to the OpenAPI document. The openapi check now requires a `default` response on every operation and a 404 only on `/events/` routes.
- **Why:** Admin sign-in for the app (Yassir, 2026-11-19), with the admin password as the first method. Sign in with Apple and email codes will add rows to the same table.
- **Decisions:**
  - Sign-out deletes the row instead of setting `revoked_at`; the plan's column wasn't needed. Expired rows are deleted on the next sign-in.
  - Without `EVENT_ACCESS_SECRET` sign-in answers 503 instead of failing open.
  - The `ADMIN_AUTH_LIMITER` key is `host-sign-in:<ip>`. **Every** attempt counts, before the password is checked, so a limited client can't tell a right guess from a wrong one.
- **Found:** the web `requireAdmin` (Basic auth) checks the password first and only then counts failures. Once limited, a wrong guess gets 429 but a right one still passes, so the limiter doesn't stop guessing. Its comparison isn't constant-time either. Fix it in its own slice.
- **Audit follow-up:** the limit is per IP only, so many IPs together can still guess. Next comes one global failure counter shared with the web Basic-auth fix. Until then, `ADMIN_PASSWORD` should be long and random. Rotating `EVENT_ACCESS_SECRET` also signs every host out.
- **Next:** the web `requireAdmin` fix plus the global counter, then the iOS admin sign-in (token in the keychain under its own service) and the admin events list.
