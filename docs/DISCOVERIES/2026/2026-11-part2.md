## [2026-11-17] Context Update — iOS join screen
- **What changed:** MomentsKit `FeatureGuest` with `JoinModel`
  (@MainActor @Observable) + `JoinView`; DesignSystem `PrimaryButtonStyle`
  and `momentsField()`; `StoredEventCredentials.nickname` (optional, still
  schema 1: older builds ignore it). App: `AppEnvironment` (live client +
  keychain, `inMemory()` for tests), RootView builds a `JoinModel` per link.
- **Flow:** link invite → `access(.invite)`; else load event; 401
  `access_required` → PIN; then nickname. A grant fetched this session is
  filed only after the event ID binds (`credentials(for:eventID:)`).
- **Claim rule:** the server mints a token only for the request that wins
  the nickname; before `GUEST_TOKENS_ENFORCED` a loser still gets 200
  without a token. iOS accepts a join only with a new token, or when the
  stored token's participant matches; otherwise "taken". Returning guests
  re-join under the stored name to confirm the token (409 → forget it).
- **Robustness:** invite kept until the access call answers (network
  errors keep it for retry); `start()` guarded against re-entry; a keychain
  failure after join keeps the one-time token in memory (`retrySaving`).
  Nickname limit counts UTF-16 like zod.
- **Debug:** scheme env `MOMENTS_API_BASE_URL` (localhost only) and
  `MOMENTS_OPEN_URL` (opens a link at launch; simulator has no universal
  links). Seed local events with `wrangler d1 execute --local`.
- **Gotcha:** `AccessGrant`/`AccessCredential`/`EventCredentials`/
  `JoinResult` now redact their descriptions; keep that for any new type
  that carries a token.

## [2026-11-17] Context Update — iOS feed screen
- **What changed:** `FeatureGuest` `FeedModel` (@MainActor @Observable over
  `FeedState`), `FeedView` + `MomentThumbnail`, `GuestEventView` (join →
  feed, "Join again" on `accessLost`), `GuestDependencies`, `ThumbnailLoader`
  (actor) and `Limiter`; `MomentsAPI.MediaFetcher`. App: `AppEnvironment.guest`.
- **Why a custom loader:** private `/media` needs `X-Event-Access`, which
  `AsyncImage` can't send. `MediaFetcher` adds it only for the API's exact
  origin (scheme/host/port, no userinfo) on the client's no-redirect,
  no-cookie session; Stream URLs get no grant. Replace with Nuke later but
  keep the same-origin rule.
- **Feed rules:** one sync at a time (`sync(waitIfBusy:)`: refresh waits for
  a poll, polls skip). Older pages run in a model-owned task (cell `.task`
  cancellation would report false failures) and carry a `generation`; a
  page requested before a first-page reload is dropped, otherwise it leaves
  a permanent gap below the new window. Arrivals hide behind
  `revealedThroughSeq` unless the grid is empty.
- **Limits:** thumbnails 15 MB streamed (`session.bytes`, refused early on
  Content-Length), `timeoutIntervalForResource` 120 s, ≤50 MP sources,
  NSCache 64 MB cost, 6 concurrent loads, abandoned downloads cancelled.
- **Reactor id:** per event = hex(HMAC-SHA256(install secret, event id))[:32];
  the 32-byte secret sits in UserDefaults (not sent). Server only stores it
  to answer `reacted`. Changing the derivation resets "my reactions".

## [2026-11-17] Context Update — signed guest media URLs (`?at=`)
- **What changed:** `mediaAccess.ts` `signMediaGrant`/`verifyMediaGrant`/
  `withGuestMediaGrants`/`withGuestMediaGrant`; v1 `signFeedMedia` (Stream
  tokens first, then `?at=` on `/media/` URLs) on feed, changes and the event
  cover; `/media` accepts `?at=` before the header/cookie check.
- **Why:** AVPlayer and image loaders can't send `X-Event-Access`; the
  planned Nuke/AVPlayer viewer needs plain URLs.
- **Token:** HMAC-SHA256(`EVENT_ACCESS_SECRET`,
  `media-grant:v1:<exp>:<access_version>:<key>`), 6 h buckets (6-12 h).
  Prefixes `grant:`, `media-view:v1:`, `media-grant:v1:`, `ip:` are prefix-free,
  so tokens can't cross uses. Bound to one key and the key's own event.
- **Limits:** bearer URL, not bound to a guest; removing one guest doesn't
  revoke issued URLs (up to 12 h). Hiding a moment does (hidden check runs
  after). Workers observability/Logpush record full URLs: keep log access
  tight and make sure no zone cache rule overrides `private` on `/media/*`.
- **Clients:** cache by path (`ThumbnailLoader.cacheKey` strips the query);
  refresh the feed for new signatures. URLs that already carry a query are
  left unsigned (none are emitted today).

## [2026-11-17] Context Update — iOS full-screen viewer
- **What changed:** `FeatureGuest/MomentViewer.swift` (iOS only), pure
  `ViewerGestures` (zoom clamp, double-tap, pan clamp, swipe-down rule),
  `Media.viewerImageURL` / `playbackURL` (MomentsDomain), `ThumbnailLoader`
  `maxBytes` + `maxConcurrentLoads`; FeedView cells are buttons.
- **Structure:** presented with `fullScreenCover(item:)`; the viewer owns its
  position (`@State current`) and closes via `dismiss`. Clearing a shared
  selection blanked the page mid-dismissal. Paging is a horizontal
  `ScrollView` + `LazyHStack` with `.scrollTargetBehavior(.paging)` and
  `.scrollDisabled(isZoomed)` (TabView can't stop paging while zoomed);
  laziness also drops far pages' decoded images.
- **Video:** `playbackURL` = Stream `hls_url`, else an http(s) R2 file; a
  Stream original is an iframe embed and never played. One `AVPlayer` per
  page, released (item cleared, audio session deactivated) on leaving;
  `.failed` shows a message.
- **Memory:** viewer loader decodes ≤2400 px, ≤40 MB downloads, 2 at a time.
- **Not yet verified on a simulator** (joining needs typing; local media is
  in real R2). Check on iOS 17 + 18: paging, zoomed pan, swipe-down, VoiceOver.

## [2026-11-18] Context Update — v1 reactions
- **What changed:** `src/worker/reactions.ts` `setReaction`; v1
  `addReaction` (PUT) / `removeReaction` (DELETE, JSON body)
  on `/events/{slug}/moments/{id}/reaction`; `REACTION_LIMITER` ratelimit
  binding (namespace 1002, 60/60 s, optional in `Env`).
- **Why idempotent:** iOS reacts optimistically and retries; the web's
  toggle would flip back on a retried request.
- **Atomicity:** visibility is part of the write (`INSERT OR IGNORE ...
  SELECT FROM moments WHERE approved`; `DELETE ... IN (visible)`), and the
  `visible` flag + count come from the same batch. A pre-SELECT raced
  deletes into an FK 500.
- **Limiter key:** `<event>:guest:<session>` with a token, else
  `<event>:ip:<CF-Connecting-IP>`; runs before any moment query.
- **Open (ship with GUEST_TOKENS_ENFORCED):** reactor ids are client-chosen,
  so one device can mint ids and inflate counts within the rate limit. On
  enforcement: reactor = token's participant id on v1 and the web toggle
  route, feed `reacted` from the token, and decide what to do with old
  device-keyed rows. Hidden moments keep hearts and can't be un-hearted.

## [2026-11-18] Context Update — iOS optimistic reactions
- **What changed:** `MomentsService.setReaction` (PUT/DELETE v1 reaction);
  `MomentsAPIError.momentNotFound/guestRequired/rateLimited`; `FeedState`
  accepts toggles while a request is in flight and
  `confirmReaction(forMomentID:reacted:reactionCount:) -> Bool` says whether
  the answer settles the moment; `FeedModel.setReacted/toggleReaction` with
  one sender Task per moment; viewer double-tap heart + heart button; cell
  heart counts.
- **Coalescing:** the sender loops: discard if the intent is back to the
  server snapshot (nothing in flight at the loop top), else send the current
  intent; an answer for an older intent re-anchors the rollback snapshot and
  loops. An answer that contradicts the request is a failure, and a sender
  makes at most 5 requests.
- **Gotcha fixed in review:** a new toggle must clear `confirmedAtLastSync`,
  or a sync read before its request landed drops the pending toggle and the
  heart flickers back.
- **Errors:** `momentNotFound` rolls back and polls (the moment leaves);
  access lost / event gone end the feed and cancel senders (no haptic);
  anything else rolls back with an error haptic (`reactionFailureCount`).
- **SwiftUI:** setting a state off then on in one update doesn't animate;
  the burst uses `keyframeAnimator(trigger:)` keyed on a tap counter.
- **Open:** `guestRequired` needs a re-join path once tokens are enforced;
  plural strings use `inflect: true` until the String Catalog lands.

## [2026-11-18] Context Update — v1 highlights and leaderboard
- **What changed:** `feed.ts` `getHighlights` (feed columns, ordered by
  hearts then seq, limit 30/max 50); `leaderboard.ts` `getLeaderboard` +
  `withRanks` (competition ranks 1, 1, 3; cap 500); v1 `getHighlights` and
  `getLeaderboard` routes behind the event gate, `no-store`.
- **Leaderboard SQL:** moments link to guests by nickname only (no
  `participant_id` on moments; `UNIQUE(event_id, nickname)` keeps it 1:1).
  Totals are aggregated once per nickname and then joined: the web's
  per-guest LEFT JOIN rescans the event's moments for every guest because
  `uploader_name` has no index. The web route still has that cost.
- **Differences from the web:** the highlights tiebreak is `seq`, not
  `created_at`; the leaderboard adds `participant_id`, `avatar_seed` and `rank`,
  and breaks ties by join time then id.
- **Limiter:** `GUEST_READ_LIMITER` (namespace 1003, 120/60 s per event and
  IP, no session lookup) on both; highlights' cost is inherent (every
  approved moment's hearts are counted before LIMIT).
- **Security note for the reactor binding (audit):** participant ids are
  public (leaderboard, join, web participants). Never use them as
  client-sent reactor ids: anyone could read (`?reactor_id=` on feed /
  highlights) or forge another guest's hearts. Derive the reactor from the
  `X-Guest-Token` session server-side and ignore the client's; if a
  wire value must stay, use `HMAC(secret, participant_id)`. Don't backfill
  old rows with participant ids.
- **Advisory points:** uploads are attributed by free-form nickname (as on
  the web), so the leaderboard is advisory until moments get a
  `participant_id` set from the guest session.
- **Open:** no `total`/`truncated` flag past 500 guests (add it when "your
  rank" is needed).

## [2026-11-18] Context Update — iOS highlights and leaderboard
- **What changed:** MomentsDomain `ReactionLedger` (heart bookkeeping
  extracted from `FeedState`), `HighlightsState` (server order),
  `ReactionList` protocol, `applyServerReaction`; FeatureGuest
  `ReactionSenders<Host: ReactionHost>` (shared sender loop),
  `HighlightsModel`, `LeaderboardModel`, `MomentBrowsing` (viewer source),
  `HighlightsView`, `LeaderboardView`, `ConfettiView`; `GuestEventView` is a
  TabView.
- **Cross-list hearts:** feed polls never carry reaction changes, so each
  list reports settled answers (`onReactionSettled`) and the other applies
  them with `applyServerReaction`: blocked only by an in-flight request
  here; over a confirmed toggle it replaces it and restarts the one-sync
  grace.
- **Loading:** no polling (the read limiter is 120/min per event and IP,
  shared on venue Wi-Fi): load on appear unless loaded in the last 30 s,
  and on pull to refresh; rate limits keep what is shown.
- **One end state:** highlights/leaderboard hand access lost or event gone
  to `FeedModel.endIfFatal`; `GuestEventView` stops both when the feed ends.
- **Review fixes:** loads are a stored `Task` that refresh/appear join (a
  bare `isLoading` guard made a pull during a load return at once, and a
  cancelled pull showed an error); senders check cancellation after the
  request too (an ended screen must not confirm or sync a late answer);
  hosts expose lists via `_modify` (a setter copies the array per tap);
  confetti keeps one cancellable stop timer and celebrations wait for the
  tab to be visible; 429 backs off tab-switch reloads for 30 s.
- **Swift 6 gotcha:** statics on a SwiftUI `View` are main-actor isolated;
  calling one from a nonisolated test traps (signal 5). Mark pure helpers
  `nonisolated`.
- **Open:** avatars are initials until the avatar endpoint lands; no
  "your rank" past 500 guests.

## [2026-11-18] Context Update — v1 upload sessions
- **What changed:** migration 0016 (`uploads.client_upload_id`,
  `participant_id` (no FK: purge deletes participants first), `caption`,
  `part_size`; unique per event+guest+client id); `uploadSessions.ts`
  (`startUpload`, `presignPartUrls`, `abortUpload`, `r2MultipartBackend`);
  v1 `POST/GET/DELETE /events/{slug}/uploads[/{id}]` + `/part-urls`;
  `UPLOAD_LIMITER` (1004, 300/60s per guest); `R2RequestError`; `momentKey`.
- **Rules:** guest token always required (new API). A retry of an existing
  client id skips limiter/caps and works after close; aborted id → 409
  `upload_not_open` (app re-queues under a new id). Caps are enforced by
  the INSERT itself (`INSERT ... SELECT WHERE counts < cap ON CONFLICT`
  on the partial index); the pre-count only saves R2 calls.
- **Part URLs:** 6 h, not 24 h: a presigned PUT binds no Content-Length, so
  a URL lets its holder write any amount until the multipart is aborted.
  The app re-requests missing parts. Finalize (next PR) must check every
  part's size via ListParts before Complete (abort on mismatch), check
  magic bytes, and refuse purged events. Signing Content-Length into the
  URL is the hard bound, but whether R2 enforces it needs a real-R2 test.
- **Purge vs open sessions:** aborts are capped per purge (subrequests), so
  rows still open are kept with guest data cleared; the daily sweeper
  aborts them and then deletes aborted rows of purged events.
- **aws4fetch retries 5xx itself** (up to 10 times), so a test faking an R2
  outage needs a 4xx; request-path calls may want fewer retries.
- **Ops:** the backstop is R2's incomplete-multipart lifecycle rule. Keep
  it at 7 days (the web queue resumes paused uploads days later); check it
  exists with `npx wrangler r2 bucket lifecycle list moments-media`.
