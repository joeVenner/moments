## [2026-11-17] Context Update — iOS join screen
- **What changed:** MomentsKit `FeatureGuest` with `JoinModel`
  (@MainActor @Observable) + `JoinView`; DesignSystem `PrimaryButtonStyle`
  and `momentsField()`; `StoredEventCredentials.nickname` (optional, still
  schema 1: older builds ignore it). App: `AppEnvironment` (live client +
  keychain, `inMemory()` for tests), RootView builds a `JoinModel` per link.
- **Flow:** link invite → `access(.invite)`; else load event; 401
  `access_required` → PIN; then nickname. A grant fetched this session is
  filed only after the event ID binds (`credentials(for:eventID:)`).
- **Claim rule:** the server mints a token only for the request that wins
  the nickname; before `GUEST_TOKENS_ENFORCED` a loser still gets 200
  without a token. iOS accepts a join only with a new token, or when the
  stored token's participant matches; otherwise "taken". Returning guests
  re-join under the stored name to confirm the token (409 → forget it).
- **Robustness:** invite kept until the access call answers (network
  errors keep it for retry); `start()` guarded against re-entry; a keychain
  failure after join keeps the one-time token in memory (`retrySaving`).
  Nickname limit counts UTF-16 like zod.
- **Debug:** scheme env `MOMENTS_API_BASE_URL` (localhost only) and
  `MOMENTS_OPEN_URL` (opens a link at launch; simulator has no universal
  links). Seed local events with `wrangler d1 execute --local`.
- **Gotcha:** `AccessGrant`/`AccessCredential`/`EventCredentials`/
  `JoinResult` now redact their descriptions; keep that for any new type
  that carries a token.

## [2026-11-17] Context Update — iOS feed screen
- **What changed:** `FeatureGuest` `FeedModel` (@MainActor @Observable over
  `FeedState`), `FeedView` + `MomentThumbnail`, `GuestEventView` (join →
  feed, "Join again" on `accessLost`), `GuestDependencies`, `ThumbnailLoader`
  (actor) and `Limiter`; `MomentsAPI.MediaFetcher`. App: `AppEnvironment.guest`.
- **Why a custom loader:** private `/media` needs `X-Event-Access`, which
  `AsyncImage` can't send. `MediaFetcher` adds it only for the API's exact
  origin (scheme/host/port, no userinfo) on the client's no-redirect,
  no-cookie session; Stream URLs get no grant. Replace with Nuke later but
  keep the same-origin rule.
- **Feed rules:** one sync at a time (`sync(waitIfBusy:)`: refresh waits for
  a poll, polls skip). Older pages run in a model-owned task (cell `.task`
  cancellation would report false failures) and carry a `generation`; a
  page requested before a first-page reload is dropped, otherwise it leaves
  a permanent gap below the new window. Arrivals hide behind
  `revealedThroughSeq` unless the grid is empty.
- **Limits:** thumbnails 15 MB streamed (`session.bytes`, refused early on
  Content-Length), `timeoutIntervalForResource` 120 s, ≤50 MP sources,
  NSCache 64 MB cost, 6 concurrent loads, abandoned downloads cancelled.
- **Reactor id:** per event = hex(HMAC-SHA256(install secret, event id))[:32];
  the 32-byte secret sits in UserDefaults (not sent). Server only stores it
  to answer `reacted`. Changing the derivation resets "my reactions".

## [2026-11-17] Context Update — signed guest media URLs (`?at=`)
- **What changed:** `mediaAccess.ts` `signMediaGrant`/`verifyMediaGrant`/
  `withGuestMediaGrants`/`withGuestMediaGrant`; v1 `signFeedMedia` (Stream
  tokens first, then `?at=` on `/media/` URLs) on feed, changes and the event
  cover; `/media` accepts `?at=` before the header/cookie check.
- **Why:** AVPlayer and image loaders can't send `X-Event-Access`; the
  planned Nuke/AVPlayer viewer needs plain URLs.
- **Token:** HMAC-SHA256(`EVENT_ACCESS_SECRET`,
  `media-grant:v1:<exp>:<access_version>:<key>`), 6 h buckets (6-12 h).
  Prefixes `grant:`, `media-view:v1:`, `media-grant:v1:`, `ip:` are prefix-free,
  so tokens can't cross uses. Bound to one key and the key's own event.
- **Limits:** bearer URL, not bound to a guest; removing one guest doesn't
  revoke issued URLs (up to 12 h). Hiding a moment does (hidden check runs
  after). Workers observability/Logpush record full URLs: keep log access
  tight and make sure no zone cache rule overrides `private` on `/media/*`.
- **Clients:** cache by path (`ThumbnailLoader.cacheKey` strips the query);
  refresh the feed for new signatures. URLs that already carry a query are
  left unsigned (none are emitted today).
